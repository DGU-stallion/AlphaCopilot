## 手法（keyless，可复现）

借用 `deepseek-harness/scripts/smoke-python-runtime.py` 的 keyless 模式：

- 起一个假的 OpenAI-兼容 SSE 端点（`127.0.0.1:<port>/v1`），`DeepSeekHarnessConfig`
  的 `base_url` / `api_key`（假 key）指过去。
- runtime 发来的第一条 request body 里：`messages[system]` = 组装后的 system prompt
  （验合规），`tools[]` = 广告给模型的工具 schema（验 get_quote / skill 可见）。
- mock 首轮返回一个对 `mcp__research__get_quote` 的 tool_call，驱动 runtime 真实执行
  我们的 MCP 工具 → 第二轮 tool 结果回流 → 验 G1-C。

## 关键技术结论

1. **skills 挂载 = skill-filesystem（提供者）+ tool-skill（模型可见的 skill 工具与目录）**。
   扁平 `.md` 文件（我们现有 5 篇）被 skill-filesystem 直接识别。
2. **合规 prompt 经 agent-spine 的 persona 注入即对模型可见**（spike 用简化版；
   正式版走 desk 的 `ctx.systemPrompt.section`，order=110）。
3. **mock 端点法是后续所有 keyless E2E 的基础手法**（T31 合规行为测试、T36 相关性场景等
   都可在无真实 key 下用它驱动 agent）。
