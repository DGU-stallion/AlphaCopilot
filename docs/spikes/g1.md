## 关键技术结论

1. **carrier 需先构建**：`python/sdk-runtime/.../runtime/` 初始无 carrier。
   在 dsh 仓库跑 `pnpm exec tsx scripts/build-exe-for-python-sdk.ts --skip-build`
   产出 node closure（118 个 @deepseek-ai 包，含 mcp-client）+ macOS-arm64 exe（206MB），
   两者都同步进 runtime 目录。
2. **两种 carrier 都可用**：`DSH_RUNTIME_MODE=node`（系统 node ≥22.19，开发）与默认
   exe（生产）都能挂载我们的 MCP server。
3. **挂载方式**：`cordis.yml` 里一个 `@deepseek-ai/dsh-mcp-client` 实例，
   `transport: stdio` + `command`/`args` 指向我们的 Python server；
   `failOnStartupError: true` 让挂载失败在 initialize 阶段暴露。
   模型看到的工具名为 `mcp__<serverName>__<rawName>`（如 `mcp__research__get_quote`）。
4. **现有产品 server 有 pre-existing 缺陷**：`packages/.../server.py` import 了未落地的
   `events` 工具（T11 未完成）会 ImportError；spike 用最小 server 隔离验证面。
   **T33 落地 MCP 时需补齐 events 等工具。**
