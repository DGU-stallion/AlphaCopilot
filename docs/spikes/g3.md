# G3 Spike — run_python 沙箱边界

**结论：通过（PASS）。** 决策 2（本机执行 + Seatbelt 隔离）成立，不必回退容器。
**日期**：2026-08-29

## 验证问题

AI 生成的 Python 在本机执行，能否用 macOS `sandbox-exec`（Seatbelt profile）
把文件读写与网络收敛到安全边界？四条断言各一：

| 断言 | 期望 | 结果 |
|------|------|------|
| A import | 沙箱内能 `import` 项目库（research） | ✓ PASS `IMPORT_OK research` |
| B write runs | 沙箱内能写 `workspace/runs/<run_id>/` | ✓ PASS 文件确实落盘 |
| C read-secret denied | 读沙箱外敏感文件被拒 | ✓ PASS `READ_DENIED PermissionError`，无泄漏 |
| D timeout killed | 死循环被 wall-clock 上限杀掉 | ✓ PASS |
| E network denied | 沙箱内发起网络连接被拒 | ✓ PASS `NET_DENIED PermissionError` |

## 关键技术结论（供 T33 落地 run_python 直接复用）

1. **不能从零 `deny default`**：Python 解释器启动需要广泛系统访问，
   从零拒绝会导致解释器在启动阶段 SIGABRT（rc=134/-6，且 stdout/stderr 全空，
   难以诊断）。**必须 `(import "bsd.sb")` 作为基座。**
2. **workspace-write 语义 = 限写不限读**：与 dsh 官方 `SandboxMode` 一致。
   profile 采用「允许读 + 拒绝写（workspace 白名单除外）+ 拒绝网络」。
3. **读 secret 被拒靠显式黑名单**，不是靠 workspace-write（后者不管读）：
   `(deny file-read* (subpath SECRET_DIR))`。生产环境把 `SECRET_DIR` 指向真实
   `~/.ssh`、`~/.aws`、`~/.config` 等。**这是黑名单，无法穷举所有敏感文件。**
4. **路径必须 resolve() 成真实路径**：macOS `/var` → `/private/var` 是符号链接，
   Seatbelt 按真实路径匹配 `subpath`，传未解析路径会导致规则静默失效
   （表现为 B/C 假失败）。这是本 spike 最初 4 条全红的根因。
5. **超时用 subprocess wall-clock**（`subprocess.run(timeout=)` → TimeoutExpired
   → kill），Seatbelt 不负责超时。

## 残余风险（已写入 ADR-0006）

- Seatbelt 管文件读写与网络，**不是容器级隔离**；敏感路径 deny 是黑名单。
- 网络 `(deny network*)` 已验证拦截（断言 E：沙箱内 `socket.create_connection`
  返回 `PermissionError`）。
- 真正强隔离仍需容器/microVM；此 profile 是纵深防御的一层。
