| 文件 | 说明 |

## 规格落实情况

| 规格 | 落实 |
|---|---|
| 主字号 12px / 次字号 11px | body 12px，所有表头/标签/副信息 11px |
| 行高 1.2 | `body{line-height:1.2}` |
| panel 间距 8px | 全部用 flex `gap:8px`，无其他间距 |
| 表格化、几乎无留白 | 全屏 11 个 panel：单元格 padding 只有 2~4px，表格行高约 19px |
| 颜色只来自 tokens.ts DARK | `:root` 的 14 个变量一一对应；JS 里 `C` 对象同一套；无渐变、无 box-shadow、无 backdrop-filter；圆角只有 0/2px |
| 涨=红 `#D9534F` 跌=绿 `#3FAE7A` | 全部数字按符号上色，A 股口径 |
| 等宽数字 | JetBrains Mono 字体栈 + `font-variant-numeric:tabular-nums`，数字全部在 `.n` 类内 |
| 内联 SVG 图表 | 4 张，全部 JS 运行时按容器实际尺寸绘制：①沪深300 分时（价格线 + 均价线 + 分时成交量）②近 10 日成交额柱状图 ③美债收益率曲线（折线 + 数据点标注）④全市场涨跌分布（左绿右红双向柱状） |

## 「这一屏我看到了什么、下一眼该看哪」

**第一眼**（视觉权重最高）：顶部关键指标条——六大指数 + 成交额 + 涨跌家数 + 涨跌停 + 封板率，
一行读完今天市场的「脸」。

**第二眼**：左列复盘看板的市场情绪格（宽度偏强 / 投机活跃 / 89 涨停 12 跌停）和那条
红绿宽度条——回答「今天钱往哪边站」。

**第三眼**：分时图和成交额柱状图——「今天怎么走的、量放没放」。

**然后按需下钻**：连板梯队表（短线情绪）→ 板块资金 / 成交额 TOP（资金去向）→
右列宏观（隔夜外围 → 大宗汇率 → 美债曲线 → 涨跌分布 → 加密）。

上→下层级是刻意的：**标题（顶栏）→ 关键指标（keystrip）→ 明细（表格/图表）**，
每一层都比下一层更「粗」一点（字号 12 vs 11、字重 700 vs 500、颜色 text vs textTertiary）。

## 密度观感的如实评价

**优点（实测）**：
- 信息量确实大：一屏约 **500+ 个数字、12 张表/图**，全部不滚动。看盘场景下「不用切换」是真实收益
- 表格行高 19px 下数字依然可读，等宽 + tabular-nums 功不可没；红涨绿跌的扫读效率高
- 顶栏 + keystrip 的两级结构让「先看哪」有明确答案，不会一打开就迷路

**缺点（也是这个方向的本质代价）**：
1. **没有喘息点**。全屏没有一个超过 20px 的留白，连续盯 10 分钟以上视觉疲劳明显
   ——这正好印证了 brief 里「D-A 适合看盘盯数据、不适合长时间阅读」的判断。
2. **11px 中文接近可读下限**。「医疗器械」「光学光电子」这类四字行业名在 11px 下
   笔画密的字（器、械、镜）开始粘连；如果真落地，行业列考虑 12px 或者只用 2 字缩写。
3. **层级靠颜色硬撑**。panel 之间只有 1px 边框区分，分组感弱；本原型靠 accent 色块
   和表头底边补救，但比 D-B 的卡片化分组「 grouping 信号」弱。
4. **没有给长文本留位置**。研报、归因说明这类内容在这个密度体系里没有容器——
   如果定 D-A，得额外定义一套「阅读态」规格（比如详情弹层用 13px/1.5）。
5. **12 格情绪统计条上标签有截断风险**。真实数据里「真实涨停」这类 4~5 字标签
   在窄格里会被 ellipsis 掉，落地时需要定列宽或缩写规范。

**结论倾向**（仅供参考，选择权在用户）：D-A 把「看盘」做到了极致，但作为**个人
投研工作台**唯一风格会牺牲阅读与思考场景；它与 D-B 的差距主要就是「要不要为
长时间停留付出密度代价」。
