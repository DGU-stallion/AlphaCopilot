### 1.1 一个重要的补充判断

**第 1 条的病根不是「没做缓存」，是 TTL 配错了。** 60s 的默认值对 8 秒的接口毫无意义。
且无缓存时**没有加载骨架**，白屏看着像卡死 —— 用户会自然认为「它每次都在重算」。

### 1.2 用户没提、但更严重的问题

- **Build 是空转的**：不是「待商榷」，是发布了永远看不见。这是第 3 条的病根。
- **宏观看板内容本来就少**（5 panel / 748 字）：不是密度不够，是**内容不足**。
  这种情况加密度只会加装饰 —— 必须先补数据源，再谈排版。

## 4. 阶段 D 的前提：先定设计风格

用户要求「先定设计风格，再用 OpenDesign 出原型，出三版比对」。

**已确定的方向（ADR-0014 + 上一轮原型评审）**：
- 终端风 / 金融科技 / 简约实用（方向 A 已是既成事实）

**待定的是「密度与排版体系」**，三个候选方向应围绕它展开：

| 候选 | 密度 | 特征 | 适合 |
|---|---|---|---|
| **D-A 彭博终端** | 极高 | 12/11px 主字号、1.2 行高、panel 间距 8px、表格化布局、几乎无留白 | 看盘、盯数据 |
| **D-B Linear / Vercel** | 中高 | 13/12px、1.4 行高、12px 间距、卡片化但紧凑、少量留白做分组 | 长时间阅读 + 操作 |
| **D-C 杂志式** | 中 | 14/13px、1.6 行高、大标题、留白做层次 | 复盘、写研究 |

> ⚠️ 用户已决定：**三种都出原型，看完再选**。所以 §4 的推荐仅作为出图时的
> 侧重参考，不要拿它替用户做决定。

**出图前的参考判断（不是结论）：D-B 可能最合适**。理由：
- 用户说「留白太多」但也说「不美观」——D-A 的极高密度容易显得拥挤（不是"不美观"的解）
- 用户是**个人使用**（自用产品），一屏看多个数是刚需，但也要能读长文本（研报、归因说明）
- D-B 在信息密度和可读性之间，且最容易和其它已定规则（tokens.ts / Num 组件）兼容

## 4.1 原型任务定义（新会话第一件事）

用 OpenDesign 出 **3 版**，每版都是**真实渲染的完整页面**，不能是线框图。

**共同要求**：
- 都用**复盘看板 + 宏观看板**这两页做样本（用户点名「两个看板」稀疏）
- 都带真实数据和真实图表（不是占位符）
- 都遵守既有硬规则：无 glass/glow/渐变、颜色来自 `tokens.ts`、等宽数字
- 都要能看出「从上而下的排版层级」（用户原话）

**三版差异（只变密度与排版，不变配色与品牌）**：

| 版本 | 字号 | 行高 | panel 间距 | 布局特征 |
|---|---|---|---|---|
| D-A 彭博终端 | 12/11px | 1.2 | 8px | 表格化、几乎无留白、一张屏塞满 |
| D-B Linear/Vercel | 13/12px | 1.4 | 12px | 卡片化但紧凑、留白只用于分组 |
| D-C 杂志 | 14/13px | 1.6 | 20px | 大标题、留白做层次 |

**验收标准**：三张截图并排能看出**明显的密度差异**，且每张都能回答
「这一屏我看到了什么、下一眼该看哪」。

### 用法（无需 CLI）

OpenDesign 桌面 App 本身就是设计工作区。两条路：

1. **在 App 里操作**（推荐，最省事）：打开 App → 新建 project → 粘贴 brief → 选 design system → 生成
2. **通过 daemon API**（可脚本化）：
   ```bash
   # 先找当前端口
   lsof -nP -iTCP -sTCP:LISTEN | grep -i "open" | grep 127.0.0.1
   curl -s --noproxy '*' http://127.0.0.1:<port>/api/skills | head -c 200
   ```

> 注意：访问本地端口必须带 `curl --noproxy '*'`。本机 shell 配了
> `http_proxy=127.0.0.1:7892`，不加会得到 **502**（踩过，误以为是服务挂了）。

### 8.4 顺带修掉的真 bug

1. **`gtimg` K 线全挂**（阻断级）：`/appstock/app/fqkline/get` 整个端点被腾讯 WAF 拦截（HTTP 501），
   而原来只试这个端点 → 回测页直接 503。修法：新增端点级回退到 `/appstock/app/kline/kline`
   （非复权，但可用），保留域名级回退。数据层冻结下属「修阻断性 bug」，已加 2 个测试 + 回归保护
   （复权可用时仍优先复权）。
2. **回撤被无条件重复计算**：`lwc_payload` 对**任何** LWC 载荷都算回撤，导致
   `tearsheet.rolling_sharpe` 带着 53 点「Sharpe 的回撤」、`backtest.drawdown` 带着
   「回撤的回撤」。改为 `with_drawdown=False` 默认 + `DRAWDOWN_FNS` 白名单
   （只有 `backtest.equity` / `walkforward.oos_equity`）。
3. **`BlockRenderer` 分派错误**（自查发现）：曾按「series 数 > 1 就走 EquityChart」，
   而 `backtest.equity` 本身就是 2 条 series（策略 vs 买入持有）→ 净值图被误判成
   「净值+回撤」。改为按 `payload.drawdown` 是否存在分派。

### 11.2 挖出的三个真 bug

**① 前端给了后端不认的选项（UI 撒谎）**
`DATE_RANGE_PRESETS` 有 2y / 3y，但后端 `_coerce_date_range` 只认 `1y`/`6m`/`3m`。
选「2 年」直接 400。→ 预设收窄到与后端一致的三个，并加测试钉住。

**② ISO 日期被静默忽略（算错）**
后端**校验通过** `"2024-01-01:2024-12-31"`，但 5 处调用点都是
`_RANGE_COUNT.get(range, 250)` —— 键对不上就默默取**最近 250 天**。
用户选了 2024，拿到最近一年，**没有任何提示**。「算错」比抛异常危险得多。

**③ `useCachedResource` 响应乱序（最隐蔽的一个）**
快速改参数时，**先发的慢请求后回来，覆盖后发的快请求结果**，界面停在
「用户已经改掉」的参数上。回测页连续改区间必复现：半年的图最快回来、
1.8 年那次最慢 → 最后显示 1.8 年的图，而参数框写着半年。

修法：`currentKey` ref 守卫 —— 缓存照写（数据本身是对的），但只有
`key` 仍是当前 key 时才更新界面状态。

**同一竞态影响任何快速改参**（快线/慢线/标的），不只是日期。
